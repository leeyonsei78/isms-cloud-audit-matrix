2.5

인증 및 권한관리

5개 항목
2.5.1

사용자 계정 관리

사용자 등록·해지 및 권한부여 절차의 적정성과 미사용(휴면) 계정의 존재 여부를 점검한다.
AWS
점검 명령어
aws iam generate-credential-report aws iam get-credential-report --query 'Content' --output text | base64 --decode aws iam list-users --query 'Users[*].[UserName,PasswordLastUsed]' --output table
문제 판단 기준
credential report의 password_last_used·access_key_last_used가 90일 이상이거나, 퇴사·전보자 계정이 Active 상태로 남아있음
개선 방안
90일 이상 미사용 IAM 사용자 비활성화·삭제, IAM Identity Center(SSO)로 개별 계정 최소화, 계정 발급·회수를 승인 이력이 남는 절차로 문서화
Azure
점검 명령어
az ad user list --query "[].{name:displayName,upn:userPrincipalName}" az role assignment list --all --query "[].{principal:principalName,role:roleDefinitionName}" -o table
문제 판단 기준
Entra ID 로그인 활동 기록(signInActivity) 상 90일 이상 미로그인 계정에 Owner·Contributor 등 역할이 남아있음, 퇴사자 계정 미삭제
개선 방안
Entra ID Access Reviews(PIM)로 정기 계정·권한 검토 자동화, 미사용 계정 비활성화, HR 연동 SCIM 자동 프로비저닝·디프로비저닝 적용
2.5.3

사용자 인증

로그인 시 사용자를 안전하게 인증하는 절차(다중인증 등)가 적용되고 있는지 점검한다.
AWS
점검 명령어
aws iam get-account-summary --query 'SummaryMap.AccountMFAEnabled' aws iam list-virtual-mfa-devices aws iam get-credential-report --query 'Content' --output text | base64 --decode
문제 판단 기준
root 계정 AccountMFAEnabled 값이 0(미설정), 콘솔 접근 권한이 있는 IAM 사용자 중 credential report의 mfa_active가 false인 사용자가 다수 존재
개선 방안
root 계정 하드웨어·가상 MFA 필수 등록 후 평상시 미사용, IAM 정책 조건(aws:MultiFactorAuthPresent)으로 콘솔·API 접근 시 MFA 강제, IAM Identity Center 전환 시 SSO+MFA 일원화
Azure
점검 명령어
az rest --method get --url "https://graph.microsoft.com/v1.0/reports/authenticationMethods/userRegistrationDetails" az rest --method get --url "https://graph.microsoft.com/v1.0/identity/conditionalAccess/policies"
문제 판단 기준
전역 관리자 등 특권 역할 계정 중 MFA 미등록자 존재, MFA를 강제하는 Conditional Access 정책이 없거나 Disabled 상태
개선 방안
Conditional Access로 전 사용자·관리자 MFA 강제 또는 Security Defaults 활성화, 특권 역할은 PIM 승격 시 MFA 재인증 필수화
2.5.4

비밀번호 관리

비밀번호의 생성·저장·변경 기준이 조직의 비밀번호 정책에 부합하는지 점검한다.
AWS
점검 명령어
aws iam get-account-password-policy
문제 판단 기준
정책 자체가 없음(NoSuchEntity 오류) 또는 MinimumPasswordLength가 8 미만, RequireSymbols·RequireNumbers가 false, PasswordReusePrevention 미설정
개선 방안
계정 비밀번호 정책을 조직 기준(예: 최소 10자 이상, 복합문자, 재사용 방지 12회, 90일 만료)으로 설정하고 정기 점검
Azure
점검 명령어
az rest --method get --url "https://graph.microsoft.com/v1.0/policies/authenticationMethodsPolicy"
문제 판단 기준
Entra ID 기본 정책(8자 이상) 외 조직이 요구하는 Smart Lockout 임계값·금지어 목록 등 강화 설정이 미적용, 하이브리드 환경에서 온프레미스 AD 정책과 불일치
개선 방안
Smart Lockout 임계값 강화, Azure AD Password Protection(맞춤 금지어 목록) 활성화, 하이브리드 환경은 온프레미스 AD 정책과 정합성 점검
2.5.5

특수 계정 및 권한 관리

root·전역관리자 등 특수 계정과 과다 권한 부여 현황을 식별하고 최소권한 원칙 준수 여부를 점검한다.
AWS
점검 명령어
aws cloudtrail lookup-events --lookup-attributes AttributeKey=Username,AttributeValue=root aws iam list-attached-user-policies --user-name USER_NAME aws iam list-policies --scope Local --only-attached --query "Policies[*].PolicyName"
문제 판단 기준
root 계정으로 일상 업무(콘솔 로그인·API 호출) 이력 존재, 다수 사용자에게 AdministratorAccess 등 광범위한 권한이 그대로 부여됨
개선 방안
root는 최초 설정·비상시에만 사용하도록 절차화, 일상 관리 업무는 Assume Role 기반 IAM Role로 전환, 업무별 최소권한 Customer Managed Policy로 세분화
Azure
점검 명령어
az role assignment list --role "Owner" --all -o table az rest --method get --url "https://graph.microsoft.com/v1.0/directoryRoles"
문제 판단 기준
구독 Owner 역할이 다수 사용자·그룹에 광범위 부여, 전역 관리자(Global Administrator) 인원이 권고 범위(2~4명)를 초과하고 상시 활성 상태로 유지됨
개선 방안
Reader·Contributor 등 세분화된 RBAC 역할과 사용자 지정 역할로 전환, 전역 관리자는 최소 인원만 유지하고 PIM으로 필요시(Just-In-Time) 승격 방식 적용
2.5.6

접근권한 검토

사용자 접근권한 및 자격증명(액세스 키 등)이 정기적으로 검토·회수되는지 점검한다.
AWS
점검 명령어
aws iam get-credential-report --query 'Content' --output text | base64 --decode aws iam list-access-keys --user-name USER_NAME aws accessanalyzer list-findings
문제 판단 기준
액세스 키 생성 후 90일 이상 미교체, 사용하지 않는 액세스 키가 활성 상태로 존재, Access Analyzer가 외부 계정·퍼블릭 공유 리소스를 탐지
개선 방안
액세스 키 90일 주기 교체 및 미사용 키 즉시 삭제, IAM Access Analyzer 상시 활성화, 분기별 권한 검토(Access Review) 절차 수립
Azure
점검 명령어
az ad sp credential list --id SP_OBJECT_ID --query "[].{keyId:keyId,endDate:endDateTime}" az role assignment list --all -o table
문제 판단 기준
서비스 프린시펄 시크릿 만료일이 1년 이상으로 설정되거나 이미 만료된 자격증명이 남아있음, 정기 Access Review가 구성되어 있지 않음
개선 방안
서비스 프린시펄은 관리 ID(Managed Identity) 또는 인증서로 전환, 부득이 시크릿 사용 시 수명을 180일 이하로 단축, Entra ID Access Reviews를 분기 단위로 자동화
2.6

접근통제

3개 항목
2.6.1

네트워크 접근

네트워크 대역별 접근통제(보안그룹·NSG 등)가 최소 허용 원칙으로 구성되어 있는지 점검한다.
AWS
점검 명령어
aws ec2 describe-security-groups --query "SecurityGroups[?IpPermissions[?IpRanges[?CidrIp=='0.0.0.0/0']]].[GroupId,GroupName]"
문제 판단 기준
0.0.0.0/0(Any)로부터 전체 포트 또는 관리 포트(22, 3389, 3306, 5432 등)가 인바운드로 열려 있음
개선 방안
보안그룹 인바운드를 업무상 필요한 출발지 IP·대역으로 제한, 관리 포트는 사내 VPN·Bastion 대역만 허용, AWS Config 규칙(restricted-ssh 등)으로 상시 탐지
Azure
점검 명령어
az network nsg list -o table az network nsg rule list --nsg-name NSG_NAME -g RESOURCE_GROUP --query "[?sourceAddressPrefix=='*']"
문제 판단 기준
NSG 규칙의 Source가 Any(*)로 설정되어 인터넷 전체로부터 인바운드가 허용됨, 특히 22·3389 포트가 전면 개방
개선 방안
NSG Source를 특정 IP·서비스 태그로 제한, Azure Bastion 또는 Just-In-Time VM Access(Defender for Cloud) 적용, Azure Policy로 Any 허용 규칙 탐지·차단
2.6.6

원격접근 통제

원격 운영 접속 경로가 안전하게 통제(전용회선, Bastion 등)되고 있는지 점검한다.
AWS
점검 명령어
aws ec2 describe-instances --query "Reservations[].Instances[?PublicIpAddress!=null].[InstanceId,PublicIpAddress]"
문제 판단 기준
퍼블릭 IP가 부여된 인스턴스에 22·3389 인바운드가 함께 열려 있어(2.6.1 결과와 교차 확인) Bastion·VPN을 거치지 않고 직접 접속 가능
개선 방안
Bastion Host 또는 Systems Manager Session Manager로 원격 접속을 일원화, 불필요한 퍼블릭 IP 회수, Session Manager 접속기록은 CloudWatch Logs로 연동
Azure
점검 명령어
az vm list-ip-addresses -o table az network bastion list -o table
문제 판단 기준
VM에 퍼블릭 IP가 직결되어 있고 RDP·SSH가 열려 있으며, Bastion·Azure AD 로그인 없이 접속이 가능한 구조
개선 방안
Azure Bastion 또는 Just-In-Time VM Access로 전환, 불필요한 퍼블릭 IP 제거, Azure AD 기반 VM 로그인(Login with Azure AD) 적용
2.6.7

인터넷 접속 통제

내부 정보시스템의 인터넷 접속(아웃바운드)이 업무 목적에 맞게 통제되는지 점검한다.
AWS
점검 명령어
aws ec2 describe-route-tables --query "RouteTables[].Routes[?GatewayId!=null]" aws ec2 describe-nat-gateways --query "NatGateways[*].[NatGatewayId,State]"
문제 판단 기준
DB 등 민감 서브넷이 인터넷 게이트웨이(IGW)로 직접 라우팅되어 있음, 보안그룹 아웃바운드가 0.0.0.0/0 전면 허용 상태
개선 방안
민감 자원은 Private Subnet + NAT Gateway 구조로 전환, 아웃바운드도 필요한 목적지·포트로 제한, VPC Endpoint로 AWS 서비스 접근 시 인터넷 경유 최소화
Azure
점검 명령어
az network route-table list -o table az network nsg rule list --nsg-name NSG_NAME -g RESOURCE_GROUP --query "[?direction=='Outbound']"
문제 판단 기준
사용자 정의 경로(UDR)가 없어 전체 아웃바운드가 인터넷으로 직접 나감, NSG 아웃바운드 규칙이 Any로 허용됨
개선 방안
Azure Firewall·NVA로 아웃바운드를 강제 라우팅(UDR), Private Endpoint로 PaaS 접근 시 인터넷 우회, NSG 아웃바운드 규칙 최소화
2.7

암호화 적용

2개 항목
2.7.1

암호정책 적용

개인정보 및 중요정보의 저장·전송 구간에 적절한 암호화가 적용되는지 점검한다.
AWS
점검 명령어
aws ec2 describe-volumes --query 'Volumes[?Encrypted==`false`].VolumeId' aws s3api get-bucket-encryption --bucket BUCKET_NAME aws rds describe-db-instances --query 'DBInstances[?StorageEncrypted==`false`].DBInstanceIdentifier'
문제 판단 기준
EBS 볼륨·RDS·S3 버킷 중 암호화가 적용되지 않은 자원이 존재(특히 개인정보·중요정보 저장소), get-bucket-encryption 조회 시 NoSuchEncryption 오류 반환
개선 방안
계정 단위 EBS 기본 암호화 활성화, S3 기본 암호화(SSE-S3·SSE-KMS)를 강제하고 버킷 정책으로 미암호화 업로드 거부, RDS는 스냅샷 복사 후 암호화 옵션으로 재생성
Azure
점검 명령어
az disk list --query "[?encryption.type=='EncryptionAtRestWithPlatformKey']" -o table az storage account show -n STORAGE_ACCOUNT --query "encryption" az sql db tde show -g RESOURCE_GROUP -s SQL_SERVER -n DB_NAME
문제 판단 기준
SQL Database의 TDE(투명한 데이터 암호화)가 Disabled 상태, 규제상 고객관리키(CMK)가 요구되는 자원에 플랫폼 기본 키만 적용되어 있음
개선 방안
비활성화된 DB의 TDE 즉시 재활성화, 규제상 요구되는 자원은 Key Vault 연동 Customer-Managed Key로 전환, Storage Service Encryption 적용 여부 상시 확인
2.7.2

암호키 관리

암호화에 사용되는 키의 생성·저장·배포·파기 및 로테이션 관리가 안전하게 이루어지는지 점검한다.
AWS
점검 명령어
aws kms list-keys aws kms get-key-rotation-status --key-id KEY_ID aws kms get-key-policy --key-id KEY_ID --policy-name default
문제 판단 기준
고객관리형 키(CMK)의 자동 로테이션이 비활성화, 키 정책의 Principal이 과도하게 넓게(예: 계정 전체 또는 *) 허용되어 있음
개선 방안
KMS 키 자동 로테이션(연 1회) 활성화, 키 정책을 특정 Role·서비스로 최소권한화, CloudTrail 데이터 이벤트로 키 사용 이력 감사
Azure
점검 명령어
az keyvault list -o table az keyvault key list --vault-name KEYVAULT_NAME az keyvault show --name KEYVAULT_NAME --query "properties.{purgeProtection:enablePurgeProtection,softDelete:enableSoftDelete}"
문제 판단 기준
Key Vault의 Soft-delete·Purge Protection이 비활성화되어 키가 영구 삭제될 위험, 키에 만료일(expiry)이 설정되지 않아 무기한 사용됨
개선 방안
Soft-delete·Purge Protection 필수 활성화, 키에 만료일 및 자동 로테이션 정책 설정, RBAC·액세스 정책으로 최소권한 부여
2.9

시스템 및 서비스 운영관리

2개 항목
2.9.4

로그 및 접속기록 관리

정보시스템의 이용·접속기록이 법적 요구사항에 맞게 생성·보존되는지 점검한다.
AWS
점검 명령어
aws cloudtrail describe-trails --query "trailList[*].[Name,IsMultiRegionTrail,IsOrganizationTrail]" aws cloudtrail get-trail-status --name TRAIL_NAME aws cloudtrail get-event-selectors --trail-name TRAIL_NAME
문제 판단 기준
CloudTrail이 일부 리전에서 비활성화되어 있거나 IsMultiRegionTrail이 false, 로그 보관 기간이 법정 요구(접속기록 2년 이상 등)에 미달
개선 방안
전 리전 CloudTrail 활성화 및 Organizations 단위 통합 추적 구성, S3 로그 버킷에 수명주기 정책으로 법정 보관기간 이상 보존, CloudWatch Logs 연동으로 실시간 모니터링
Azure
점검 명령어
az monitor diagnostic-settings list --resource RESOURCE_ID az monitor log-analytics workspace list -o table az monitor activity-log list --start-time 2026-05-01
문제 판단 기준
핵심 리소스(구독, 주요 VM·DB)에 진단 설정(Diagnostic Settings)이 구성되지 않아 로그가 수집되지 않음, Activity Log 보존기간이 기본값(90일)에 그쳐 법정 보관기간 미달
개선 방안
전 구독·핵심 리소스에 Diagnostic Settings를 Log Analytics·Storage Account로 연동, Storage 수명주기 정책으로 장기보관(2년 이상), Azure Policy(Deploy if not exists)로 진단설정 강제
2.9.5

로그 및 접속기록 점검

저장된 로그의 위·변조 방지 조치와 정기적인 점검·분석이 이루어지는지 점검한다.
AWS
점검 명령어
aws cloudtrail get-trail-status --name TRAIL_NAME --query "LogFileValidationEnabled" aws s3api get-bucket-policy --bucket LOG_BUCKET aws s3api get-public-access-block --bucket LOG_BUCKET
문제 판단 기준
로그파일 무결성 검증(Log File Validation)이 비활성화, 로그 버킷이 일반 관리자에게 삭제·수정 권한을 부여하거나 퍼블릭 접근이 가능
개선 방안
Log File Validation 활성화(SHA-256 다이제스트 서명), 로그 버킷을 별도 계정으로 분리 후 Object Lock(WORM)·최소권한 정책 적용, 월 1회 이상 로그 검토·이상탐지 자동화(Athena 등)
Azure
점검 명령어
az storage account blob-service-properties show -n STORAGE_ACCOUNT --query "{immutability:immutableStorageWithVersioning,softDelete:deleteRetentionPolicy}" az role assignment list --scope WORKSPACE_ID -o table
문제 판단 기준
로그 저장 Storage Account에 불변성(Immutable Blob Storage)이 설정되지 않아 변조·삭제가 가능, Log Analytics Workspace에 과다한 사용자가 편집 권한을 보유
개선 방안
Immutable Blob Storage(WORM) 정책 적용, Workspace RBAC를 Reader 중심으로 최소화, 관리자 로그인·권한변경 기준 쿼리로 정기 로그 점검 자동화(Sentinel·Workbook)

2.10.2

클라우드 보안

AWS
점검 명령어
aws cloudtrail lookup-events --lookup-attributes AttributeKey=EventName,AttributeValue=ConsoleLogin aws organizations describe-organization aws securityhub get-findings --filters '{"ComplianceStatus":[{"Value":"FAILED","Comparison":"EQUALS"}]}'
문제 판단 기준
콘솔 로그인 이벤트에 비정상 위치·시간대 접속 존재, Organizations SCP 등 계정 간 가드레일 미설정, Security Hub 컴플라이언스 FAILED 항목 다수
개선 방안
Organizations + SCP로 계정 단위 가드레일 설정, Security Hub·Config Conformance Pack으로 CIS AWS Foundations 벤치마크 상시 점검, 콘솔 로그인 이상탐지에 GuardDuty 연계
Azure
점검 명령어

문제 판단 기준
관리 그룹·Azure Policy가 미적용되어 구독 간 보안기준이 불일치, Defender for Cloud 보안 점수(Secure Score)가 저조하거나 규제 준수 표준 항목이 미충족
개선 방안
관리 그룹 단위 Azure Policy(Deny·Audit)로 조직 전체 가드레일 구성, Defender for Cloud 상시 활성화 및 Secure Score 개선항목 조치, 구독 소유자 변경 등 주요 이벤트 알림(Action Group) 설정
2.10.8

패치관리

운영체제 및 소프트웨어의 보안 패치가 적시에 식별·적용되는지 점검한다.
AWS
점검 명령어
aws ssm describe-instance-information --query "InstanceInformationList[*].[InstanceId,PingStatus]" aws ssm list-compliance-items --resource-id INSTANCE_ID aws ssm describe-patch-group-state --patch-group PATCH_GROUP
문제 판단 기준
Systems Manager 관리 대상에 등록되지 않은 인스턴스가 존재(패치 관리 사각지대), Patch Compliance 상태가 NON_COMPLIANT인 인스턴스가 다수
개선 방안
전 EC2에 SSM Agent 설치 및 Patch Manager 베이스라인·일정 적용, Maintenance Window로 정기 패치 자동화, Compliance 대시보드로 미준수 인스턴스 상시 추적
Azure
점검 명령어
az vm assess-patches -g RESOURCE_GROUP -n VM_NAME az automation software-update-configuration list --automation-account-name AUTOMATION_ACCOUNT -g RESOURCE_GROUP
문제 판단 기준
Automatic VM Guest Patching이 미설정, Update Management(Azure Automation)에 등록되지 않은 VM이 존재, 평가 결과 Critical·Security 패치가 다수 미적용
개선 방안
Automatic Guest Patching 활성화 또는 Azure Update Manager로 일원화, Maintenance Configuration으로 정기 패치 일정 수립, 패치 준수율 대시보드로 상시 추적

2.11.2

취약점 점검 및 조치

정기적인 취약점 점검을 수행하고 발견된 취약점이 기준에 따라 조치되는지 점검한다.
AWS
점검 명령어
aws inspector2 batch-get-account-status aws inspector2 list-findings --filter-criteria '{"severity":[{"comparison":"EQUALS","value":"CRITICAL"}]}'
문제 판단 기준
Inspector2가 일부 계정·리전에서 비활성화되어 있음, CRITICAL·HIGH 등급 취약점이 장기간 조치되지 않은 채 방치됨
개선 방안
전 계정·리전에 Inspector2 활성화(EC2·ECR·Lambda 스캔), 취약점 등급별 조치 SLA(예: Critical 7일 이내)를 수립하고 티켓 시스템과 연동, 정기 리포트로 경영진 보고
Azure
점검 명령어
az security assessment list --query "[?status.code=='Unhealthy']" az security sub-assessment list
문제 판단 기준
Defender for Cloud 취약점 평가가 일부 리소스에 구성되지 않음, Unhealthy 평가 항목이 장기간 조치되지 않고 누적됨
개선 방안
Defender for Servers·Containers 등 플랜을 활성화해 취약점 스캔을 자동화, Unhealthy 항목을 SLA로 관리하고 Secure Score에 반영, 월 1회 이상 취약점 리포트 검토
2.11.3

이상행위 분석 및 모니터링

침해사고 징후를 탐지하기 위한 이상행위 분석·모니터링 체계가 구축·운영되는지 점검한다.
AWS
점검 명령어
aws guardduty list-detectors aws guardduty get-detector --detector-id DETECTOR_ID aws guardduty list-findings --detector-id DETECTOR_ID
문제 판단 기준
GuardDuty가 비활성화되어 있음, 활성화된 경우에도 High·Critical Finding이 장기간 확인·대응되지 않고 누적됨
개선 방안
전 계정·리전에 GuardDuty 활성화(Organizations 위임 관리자로 중앙화), Finding을 EventBridge+SNS 또는 SOAR로 자동 알림·대응 연계, 위협 인텔리전스 룰셋 정기 갱신
Azure
점검 명령어
az security alert list --query "[?status=='Active']" az security auto-provisioning-setting list
문제 판단 기준
Defender for Cloud Active Alert이 다수 미해결 상태로 누적됨, 자동 프로비저닝(모니터링 에이전트 배포)이 비활성화되어 일부 리소스가 모니터링 사각지대에 있음
개선 방안
Defender for Cloud 전체 플랜과 Auto-provisioning 활성화, Microsoft Sentinel 연동으로 상관분석·자동대응(Playbook) 구성, Active Alert 대응 SLA 수립

2.12.1

백업 및 재해복구

재해·재난 발생에 대비한 백업 및 이중화 조치가 마련되어 있는지 점검한다.
AWS
점검 명령어
aws backup list-backup-plans aws backup list-backup-jobs --by-state FAILED aws dlm get-lifecycle-policies
문제 판단 기준
중요 자원(RDS·EBS·EFS)에 백업 계획(Backup Plan)이 연결되어 있지 않음, 최근 백업 Job이 FAILED 상태로 다수 존재, 백업 보관 리전이 운영 리전과 동일해 재해 시 동반 손실 위험
개선 방안
AWS Backup으로 전사 백업 정책을 RPO·RTO 기준에 맞게 표준화, Cross-Region Copy로 이중화, 정기 복구 테스트(Restore Test)를 수행하고 결과를 기록·보고
Azure
점검 명령어
az backup policy list -g RESOURCE_GROUP --vault-name VAULT_NAME az backup item list -g RESOURCE_GROUP --vault-name VAULT_NAME --query "[?properties.lastBackupStatus=='Failed']" az backup vault list --query "[].properties.storageType"
문제 판단 기준
Recovery Services Vault에 정책이 연결되지 않은 자원이 존재, lastBackupStatus가 Failed인 항목이 다수, StorageType이 LocallyRedundant(LRS)로 지역 재해 시 손실 위험
개선 방안
Recovery Services Vault를 GRS(Geo-Redundant)로 구성, 백업 실패 알림(Azure Monitor Alert) 설정, 연 1회 이상 DR 복구 모의훈련을 수행하고 결과 문서화
